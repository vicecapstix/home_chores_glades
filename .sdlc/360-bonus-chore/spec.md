# Spec: bonus chore of the day (#360)
**Behaviour:** admin picks one chore and +1..20 points for today. Stored at `state/bonusChore {date, taskId, extra}` (date = local today when set). `bonusFor(task, now)` returns `extra` only for that task on that local date, else 0 (read-time expiry; stale node is ignored and overwritten/cleared by the admin). On tick, `earned = taskPoints * doublePointsMultiplier + bonusFor(tick time)`, stored in `lastDonePoints` and history, so uncheck reverses exactly. Judged at the tick time, so a parent-check approved the next day still pays what the child ticked for.
**UI:** card (phone/tablet/TV share `cardHTML`) shows `⭐ +N today` and the total in the `+N pts` tag, not once done. Admin panel: "Bonus chore today" select + points + Set/Clear. Member: sees the tag only. Readonly TV: tag only, no form, no writes.
**Data shape:** one new bounded root node `bonusChore` (applySnapshot, cache snapshot). Firebase rules unchanged (`/state` already writable).
**Security/RBAC:** `setBonusChore`/`clearBonusChore` start with `if (READONLY || !isAdminFn()) return false`; `isAdminFn` passed in from main.js. Chore names escaped with `esc()` in the admin select. Validation: known task, integer 1..20.
**Cost guardrails:** one tiny node (<100 bytes), no new reads beyond the existing `/state` listener; no services, deps or rules.
**Flagged concerns:** `src/restore.js` and member rename are untouched, so a restore drops `bonusChore` (acceptable: it is a one-day setting) and a chore deletion leaves a stale node that is ignored (bonusFor needs the task id to match; the admin form only lists live chores).
