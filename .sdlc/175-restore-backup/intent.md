# Intent: #175 Restore from a JSON backup (admin, with safety backup first)

Queue position: 3

## Problem
Admins can download a backup (#93) but can't restore one, so the backup can't help after an accidental bulk delete or a bad template apply.

## Outcome / acceptance criteria
- [ ] Admin Panel → "Restore backup…" opens a file picker (`.json`), validates `schemaVersion` and shape, and shows a summary (members, chores, history count, exported date)
- [ ] Requires typing RESTORE to confirm. First it downloads a fresh backup of the current data automatically
- [ ] Restore keeps every existing member's current `pinHash` (backups have none) and never imports a `pinHash` from the file
- [ ] Caps are enforced on import (history ≤ 500, redemptions ≤ 100, rewards ≤ 50, template caps), and names are validated like the normal add paths
- [ ] Writes in one operation that keeps `nextId`
- [ ] Guards: `READONLY || !isAdmin()`; tests for validation, PIN preservation, caps and the write payload (mocked Firebase)

## Affected users
Admin.

## Constraints
- Cost guardrails: stays on GitHub Pages (`main` / root) and the existing Firebase RTDB on the free Spark plan. No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep history capped at 500 and reads small. Never write to or change rules on the live DB; tests use mocks only.
- Runs only when an admin picks a file in the app; agents never run it against the live DB.
- File stays on the device; no upload anywhere.
- Deploy: run `npm run build:pages` and commit the root files so merging deploys (CI fails on drift).
