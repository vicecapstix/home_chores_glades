## Problem
Found by the weekly deep bug hunt (reproduced). The rollover timer (`src/rollover.js`, #88) calls `checkTaskResets()` on its tick but not `checkPauseExpiry()` / `checkAwayExpiry()`, which only run on a database snapshot (`src/main.js`). `checkTaskResets` returns early while `state.pause` is set, but `isPausedNow` (`src/utils.js`) is date-based. So on a phone or TV left open past the pause end with no other device writing, yesterday's daily chores stay "done", while chores whose `lastDone` should have been shifted on resume already show "Overdue". Same gap for a member's away end.

## Outcome / acceptance criteria
- [ ] The rollover tick runs the pause and away expiry checks before `checkTaskResets` (READONLY: no writes, display still correct)
- [ ] A screen left open across the pause end resets daily chores and shifts `lastDone` exactly as a fresh snapshot would
- [ ] Same for a member's `awayUntil` passing
- [ ] Running on several devices at once gives the same result (idempotent patches)

## Affected users
Readonly TV left on all day; phones/tablets left open.
