# Intent — #309 Undoing a Skip wipes a tick made inside the undo window

## Problem
Found by the weekly deep bug hunt (failing test reproduced). Skip's undo (`src/tasks.js` ~516) blindly writes back the previous `lastDone`/`skippedAt`. If someone ticks the chore on another device inside the 5 s undo window and the admin then taps Undo, the old `lastDone` (days ago) is written while `done` is true; `checkTaskResets` immediately resets it and clears `lastDoneBy`, but the points and history stay — the child can tick it again and be paid twice.

## Outcome / acceptance criteria
- [ ] Undo of a Skip does nothing (with a toast) if the live task is now done or its `lastDone !== skippedAt`
- [ ] Undo straight after a Skip still restores `lastDone`/`skippedAt` as today
- [ ] READONLY / non-admin guards unchanged

## Affected users
Admin (skip/undo), members ticking on another device.

## Constraints
- Cost guardrails: stays on GitHub Pages (`main` / root) and the existing Firebase RTDB on the free Spark plan. No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep data bounded (history cap 500, redemptions cap 100) and reads small. Never write to or change rules on the live DB; tests mock Firebase.
- Prefer a Firebase transaction or a check against live state; keep the write granular.
