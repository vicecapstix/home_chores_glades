# Intent — #310 Offline "Last updated" jumps to now after a local tick

## Problem
Found by the weekly deep bug hunt (failing test reproduced). The `/state` `onValue` handler in `src/main.js` (~156) calls `markSynced()` (and `saveSnapshot` stamps `savedAt`) on every event — Firebase also fires it for local writes made while offline. So after a child ticks a chore offline at 14:40, the banner says "Last updated 14:40" although nothing has come from the server since 14:05 (#258 follow-up).

## Outcome / acceptance criteria
- [ ] While `.info/connected` is false, local events don't move "Last updated" or the cache `savedAt`
- [ ] Coming back online and receiving a server snapshot updates it as today
- [ ] Banner text otherwise unchanged

## Affected users
Members and admins on phones/tablets with flaky Wi-Fi.

## Constraints
- Cost guardrails: stays on GitHub Pages (`main` / root) and the existing Firebase RTDB on the free Spark plan. No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep data bounded (history cap 500, redemptions cap 100) and reads small. Never write to or change rules on the live DB; tests mock Firebase.
- Display/cache only; no database writes.

## Open questions
None.

## Verification
Vitest: connected=false → local event → banner keeps the earlier time; connected=true → server event updates it. Build passes.
