## Problem
When the connection drops, the offline banner (`src/connection.js`) doesn't say how old the data on screen is. On a TV left on all day a parent can't tell whether the board is current.

## Outcome / acceptance criteria
- [ ] The app records the time of the last live snapshot (in memory, plus the existing device cache from #146)
- [ ] Offline banner / sync dot tooltip shows "Last updated 14:05" (or "yesterday 21:10")
- [ ] On a cached start it shows the cache time until the first live snapshot
- [ ] Display only; no new DB reads or writes

## Affected users
Everyone, especially the readonly TV view.

## Constraints
- Cost guardrails: stays on GitHub Pages (`main` / root) and the existing Firebase RTDB on the free Spark plan. No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep data bounded (history cap 500, redemptions cap 100) and reads small. Never write to or change rules on the live DB; tests mock Firebase.

## Open questions
None.

## Verification
Vitest with fake timers: snapshot at 14:05, then disconnect → banner text contains "14:05"; cached start shows the cached time.
