# Intent — #103

**Uncheck after spending points lets members farm free rewards; uncheck also subtracts last week's points from this week**

Queue position: 4

## Problem
`toggleTask` (`src/tasks.js:178-189`) reverses points on uncheck with `Math.max(0, points - lastDonePoints)` from the local cache. Repro: Alice (0 pts) ticks a 24-pt chore → 24 pts; requests a 24-pt reward (`spendPoints` → 0); unchecks the chore → stays 0 (clamped, nothing clawed back); ticks it again → 24. Each cycle buys another reward. Points are also written as an absolute value from local `m.points`, so a spend made on another device before the snapshot arrives is overwritten. Separately, unchecking a weekly chore ticked last Sunday subtracts its points from *this* week's `weekPoints`.

## Outcome / acceptance criteria
- [ ] Uncheck by a non-admin is refused with a toast ("Points already spent — ask a parent") when the member's balance is below `lastDonePoints`
- [ ] Admin uncheck still works; the balance may go below zero and the leaderboard shows it (no silent clamp)
- [ ] Point award and reversal use `runTransaction` (or `increment()`) on the member's `points` / `weekPoints` instead of absolute values from cache
- [ ] Check stores the week start it counted in (e.g. `lastDoneWeek`); uncheck only subtracts from `weekPoints` when that matches the current week
- [ ] Tests: check → spend → uncheck (member refused, admin goes negative); concurrent spend not overwritten (mocked transaction); last-week uncheck leaves this week's points
