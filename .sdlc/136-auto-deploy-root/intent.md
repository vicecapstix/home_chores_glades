# Intent: #136 Every merge makes all other open PRs conflict on the committed index.html bundle


## Problem
Each PR commits the rebuilt single-file bundle (`index.html`, ~455 kB minified, one line) because GitHub Pages serves `main` / root. Any merge changes that file, so every other open PR becomes un-mergeable. On 22 Oct all 7 open PRs (#128–#132, #134, #135) were `dirty`, and a trial merge of `main` into each showed `index.html` as the **only** conflicting file. Every merge forces a rebuild-and-push on every other PR, which slows review and re-runs CI.

## Outcome / acceptance criteria
- [ ] PRs no longer need to commit the built `index.html` (or a conflict on it resolves automatically)
- [ ] GitHub Pages still serves `main` / root, and the live site updates after a merge with no manual step
- [ ] CI still proves that `src/` builds, and the deployed root files still match `src/` after every merge
- [ ] CLAUDE.md and the daily-run instructions describe the new flow

## Affected users
Admin/JT (reviews and merges); indirectly everyone (fixes ship faster).

No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep history capped at 500 and reads small. Never write to or change rules on the live DB; tests use mocks only.
- Must stay on GitHub Pages from `main` / root (no switch to an Actions-based Pages deploy unless JT agrees), free standard GitHub-hosted runners only.
