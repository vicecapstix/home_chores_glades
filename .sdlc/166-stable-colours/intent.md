## Problem
Colours come from the member's index in `getMembers()` (`pColor` in `src/ui.js`, plus `render.js`, `history.js`, `tv.js`, `auth.js`). Firebase returns member keys sorted alphabetically, so adding "Aaron" or renaming someone changes everyone's colour on chips, chore tags, History, the leaderboard and the TV. Kids recognise their colour, so this is confusing.

## Outcome / acceptance criteria
- [ ] A member's colour stays the same when other members are added, renamed or removed
- [ ] Approach: store `colorIdx` on the member when added (and backfill missing ones on first admin load with one multi-path update), or a stable hash of a stored id. Renaming keeps the colour
- [ ] All five places use one helper (`pColor`)
- [ ] Tests: add a member alphabetically first → existing colours unchanged; rename keeps colour
