## Problem
The site deploys several times a week, but a TV, tablet or phone left open keeps running the old bundle for days (the service worker is network-first, but nothing reloads the page). Fixes and new features don't reach the TV until someone reloads it by hand.

## Outcome / acceptance criteria
- [ ] When a new service worker takes control (`controllerchange`) or a periodic check (e.g. hourly `registration.update()`) finds a new version, phones/tablets show a small "New version — tap to refresh" banner
- [ ] On the readonly TV view the page reloads itself automatically when idle (no open modal), at most once per new version
- [ ] Never reloads mid-edit on an editing device; no reload loop if the update fails
- [ ] Works when the service worker isn't registered (dev, http) — feature simply off

## Affected users
Readonly TV (main beneficiary), members and admins on phones/tablets.

## Constraints
- Cost guardrails: stays on GitHub Pages (`main` / root) and the existing Firebase RTDB on the free Spark plan. No Blaze-only features (Functions, Storage, Extensions), no new services, API keys, secrets or paid hosting. Keep data bounded (history cap 500, redemptions cap 100) and reads small. Never write to or change rules on the live DB; tests mock Firebase.
- Changes in `src/pwa.js` / `src/main.js` only. Avoid changing `src/public/sw.js` (always-JT for the review gate); if that turns out to be needed, say "Needs JT" in the PR.
- `registration.update()` fetches only sw.js from GitHub Pages — no Firebase reads.

## Open questions
None — default check every 60 min.
