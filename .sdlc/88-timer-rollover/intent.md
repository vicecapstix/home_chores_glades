# Intent - #88

## Screens left open never roll over: resets and overdue status only update on a database change

Queue position: 2

## Problem
Chore resets and due/overdue status are only recalculated when a Firebase snapshot arrives (`src/main.js:96` calls `checkTaskResets()` then `render()` inside `onValue`). Nothing re-runs them on a timer (the only intervals are the TV clock in `src/tv.js:57` and notifications). A screen left open overnight — the TV (`?readonly=1`), a wall tablet, or a phone tab — keeps showing yesterday's daily chores as done and "due soon" chores never turn overdue until someone else changes something in the database. Confirmed on main (bc0bca3).

## Outcome / acceptance criteria
- [ ] A local timer (about every 60 s, plus on `visibilitychange` → visible) re-runs `checkTaskResets()` and re-renders only when a task's due status or done flag would change (no needless full re-render that wipes inline edits — keep #34 behaviour)
- [ ] TV view (`READONLY`) rolls over locally at local midnight with no writes
- [ ] Non-readonly clients still write resets with the existing granular `patchRoot` (idempotent if several devices do it)
- [ ] No extra Firebase reads or listeners
- [ ] Tests with fake timers: a done daily task becomes not-done after local midnight without a snapshot; a 'soon' task becomes 'overdue'; READONLY makes no write

## Affected users
Readonly TV view (main case), admin and members with the app left open.
